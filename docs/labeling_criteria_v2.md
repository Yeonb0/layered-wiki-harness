## 1. 대상 · 단위 · 뷰

### 대상

- 라벨 단위는 세그먼트다. 라벨러는 세그먼트마다 고유 층 하나를 매긴다.
- 라벨 대상은 출처가 team_1jo · team_soft_eng 인 세그먼트다 ( 701개, 파일럿 · 본실험 분리 전 ).
- Lecture Note ( 출처 층 전사 ) 세그먼트는 라벨링하지 않는다. 정답 합성 ( 4 장 ) 에서 고유 층과 무관하게 정답이 전사이기 때문이다. 이 세그먼트의 정답은 auto = true 로 표시한다.

### 라벨러 뷰

- 문서 단위로 보여준다 : title 한 줄, 그 아래에 세그먼트 텍스트를 문서 순서대로 잇고 각 세그먼트 앞에 순번 표지 [n] 을 붙인다. 라벨러는 표지마다 층을 매긴다.
- 보여주지 않는 것 : zip 안 경로, doc_id, 출처 ( source ), 출처 층, 그룹 ( 개인 페이지 주인 · 팀 ), properties ( 과목 · 선택 · 날짜 · 참여자 등 ), 코퍼스의 다른 문서. 문서는 순번으로만 식별한다.
- 이미지 줄은 원문 줄 ( 파일 이름 ) 그대로 보여주고 이미지 파일은 열지 않는다.
- 원칙 : 라벨러 입력 ⊆ 에이전트 입력. 에이전트 입력은 이 뷰의 title 과 본문을 포함해야 한다. 라벨링 도구는 문서 뷰 문자열의 해시를 view_sha256 으로 남긴다.
- 문서 제시 순서는 시드 고정 무작위 순서다. 시드는 라벨링 시작 전에 커밋한다 ( 값 미결정 ).

## 2. 층 정의 ( 고유 층 )

### 공통

- C1 핵심 판정 ⟨이식⟩ : 층은 세그먼트의 핵심으로 정한다. 핵심은 세그먼트가 내세우는 결정 · 계획 · 의견 · 설명 · 기록이다. 지워도 세그먼트가 말하는 바가 달라지지 않는 부분 ( 출처 언급, 이름 언급, 인사말, 한두 줄의 메모, 다른 문서 안내 ) 은 부수이며 층을 정하지 않는다.
- C2 근거 범위 : 라벨러는 라벨러 뷰 ( 같은 문서의 다른 세그먼트 포함 ) 와 자신의 일반 지식만 쓴다. 코퍼스의 다른 문서, 경로, 검색은 쓰지 않는다.
- C3 집단 ⟨이식⟩ : 이 기준에서 팀은 함께 과제나 제품을 만드는 실제 작업 집단이다. 수업 · 시험 · 교재를 낸 기관은 팀이 아니다.

### 개인

- 정의 ⟨이식⟩ : 한 사람의 생각 · 조사 · 작업 과정이 핵심이고, 팀이 그것을 채택했다는 표시가 세그먼트에 없는 내용.
- P1 ⟨이식⟩ : 한 사람의 아이디어 초안 · 제안 · 의견 · 소감이 핵심이다 ( 합성 예 : "이런 기능을 넣으면 어떨까 싶다" ).
- P2 ⟨이식⟩ : 한 사람의 할 일 · 계획 · 준비 메모 · 진행 체크가 핵심이다 ( 합성 예 : "회의 전까지 경쟁 앱 세 개 써 보기" ).
- P3 ⟨이식⟩ : 한 사람의 시행착오 · 디버깅 · 개인 환경 기록이 핵심이다.
- 반례 ⟨이식⟩ : 1인칭이 있어도 핵심이 일반 지식 설명이면 개인이 아니다 ( O1 ). 개인이 쓴 글이어도 팀이 정한 내용을 옮겨 적은 것이면 팀이다 ( T1 · T2 ).

### 팀

- 정의 ⟨이식⟩ : 특정 팀의 결정 · 운영 · 산출물이 핵심이어서, 그 팀 밖으로 옮기면 참이 아니게 되거나 뜻이 바뀌는 내용.
- T1 ⟨이식⟩ : 팀이 내린 결정 · 합의 · 확정이 핵심이다 ( 합성 예 : "로그인은 소셜 로그인만 지원하기로 했다" ).
- T2 ⟨이식⟩ : 팀 운영이 핵심이다 : 역할 분담, 일정 · 마감, 회의 안건 · 진행, 할 일 배정, 팀에 주어진 과제 명세 · 평가 기준.
- T3 ⟨이식⟩ : 팀 산출물의 명세가 핵심이다 : 그 팀의 서비스 · 과제에 대한 기획, 요구 사항, 기능, API, 화면, 데이터 설계, 분석 결과.
- T4 ⟨이식⟩ : 팀 내부 명칭 · 고유 설정이 핵심이다 ( 서비스 이름, 캐릭터 · 세계관 설정, 내부 약어 ).
- 반례 ⟨이식⟩ : 팀 문서 안에 있어도 핵심이 일반 지식 설명이면 팀이 아니다 ( O1, BB1 ). 팀 이름이나 팀원 이름이 나온다는 것만으로 팀이 되지 않는다 ( BB5 ).

### 전사

- 정의 ⟨이식⟩ : 핵심이 특정 팀 · 개인과 무관하게 참인 일반 지식.
- O1 치환 시험 ⟨이식⟩ : 다른 팀이나 조직의 문서에 이 세그먼트를 그대로 옮겨도 핵심을 고칠 필요가 없다.
- 반례 ⟨이식⟩ : 일반 개념이어도 핵심이 그 팀의 선택 · 적용 방식이면 팀이다 ( BB1 ). 일반 개념이어도 핵심이 한 사람의 시행착오면 개인이다 ( P3 ).

## 3. 판정 순서 ⟨이식⟩

1. C1 로 핵심과 부수를 가른다. 이후 단계는 핵심만 본다.
2. P1 · P2 · P3 중 하나라도 걸리면 개인.
3. T1 · T2 · T3 · T4 중 하나라도 걸리면 팀.
4. O1 을 통과하면 전사.
5. O1 이 실패했다면 실패 이유가 되는 팀 고유 요소가 있다는 뜻이므로 3 단계로 돌아가 해당 T 조항을 찾는다.
6. 핵심이 너무 적어 2 ~ 4 단계를 판정할 수 없거나, 5 단계에서도 조항을 찾지 못하면 기본값 D0 = 전사.

두 조항에 동시에 걸리면 낮은 층이 이긴다. 핵심에 하위 층 성격이 있는 내용을 상위 층에 두면 그 내용이 상위 층으로 올라가기 때문이다.

- D0 는 default_applied = true 로 기록하고 층 분포를 보고할 때 D0 건수를 나란히 적는다. 팀 출처 세그먼트에서 D0 = 전사는 정답을 출처보다 위로 올리므로, D0 건수와 그중 정답 > 출처 건수를 따로 보고한다.
- 강제 선택이다. 보류 라벨은 없다. 확신도를 기록한다 : 3 = 조항 하나가 바로 걸림, 2 = 경계 조항 ( BB ) 으로 정함, 1 = 다른 층도 그럴듯함 ( D0 는 항상 1 ). 확신도로 정답을 거르지 않는다.

### 경계 조항 ⟨이식⟩

| id | 경계 | 상황 | 판정 |
| --- | --- | --- | --- |
| BB1 | 전사 ↔ 팀 | 팀 문서 안의 일반 지식 설명 ( 기술 개념, 외부 서비스 · 플랫폼의 일반 사실 ) | 설명 자체가 핵심이면 전사. 그 지식을 팀이 어떻게 고르고 적용하는지가 핵심이면 팀 ( T1 · T3 ) |
| BB2 | 팀 ↔ 개인 | 의견 · 제안과 결정이 함께 있다 | 결정 · 확정 · 합의 표시가 핵심이면 팀 ( T1 ), 제안 단계의 의견이 핵심이면 개인 ( P1 ) |
| BB3 | 전사 ↔ 개인 | 한 사람이 외부 자료를 요약한 학습 · 조사 메모 | 요약된 일반 지식이 핵심이면 전사. 본인의 판단 · 적용 계획이 핵심이면 개인 ( P1 · P2 ) |
| BB4 | 팀 ↔ 개인 | 팀원 한 명이 팀 산출물 초안을 쓴다 | 팀이 채택했다는 표시가 없으면 개인 ( P1 ). 팀 산출물 문서에 들어간 명세면 팀 ( T3 ) |
| BB5 | 전 층 | 사람 이름 · 팀 이름 · 수업 이름이 나온다 | 이름은 층을 정하지 않는다. 역할을 배정하는 내용이면 T2 |
| BB6 | 전 층 | 표 · 목록 · 이미지 줄만 있다 | 항목 내용으로 판정. 판정할 수 없으면 D0 |

## 4. 정답 층 합성

- 층 순서 : 개인 < 팀 < 전사.
- 합성 규칙 ⟨이식⟩ : 세그먼트 고유의 층을 판정한 뒤, 그 층이 출처 층보다 낮으면 출처 층으로 올린다. 정답 층 = max ( 출처 층, 고유 층 ).
- 출처 층은 세그먼트 규칙 v1.1 의 layer ( Notion 위치 ). 라벨러는 출처 층을 모른다.
- 올라간 세그먼트는 clamped = true. 하위 층 정답은 두지 않는다 ( 하향 배치 정답 없음 ).
- 정답 그룹 : 정답 층 = 출처 층이면 출처 그룹. 개인 출처에서 정답이 팀이면 주인이 속한 팀 ( 1조 ). 정답이 전사면 그룹 없음.
- Lecture Note : 라벨 없이 정답 전사, auto = true.
- 결과로 보고할 비율 : 정답 = 출처, 정답 > 출처 ( 상향 배치가 필요한 세그먼트 ), clamped. 비율을 보고 규칙을 고치지 않는다.

## 5. 일치도

- 관문 : 명목 Cohen κ, 고유 층 라벨 기준. 자기 일치도 ≥ 0.80, 제3자 ≥ 0.67. 보조 : 선형 가중 κ, 원 일치율, 3 × 3 혼동 행렬, 층별 · 조항별 일치율, D0 비율.
- 자기 일치도 : 재라벨 표본을 1회차 전에 시드로 뽑아 커밋한다. 2회차는 1회차 마지막 건으로부터 14일 이상 뒤, 새 시드 순서, 1회차 파일을 열지 않는다. 2회차는 일치도 계산에만 쓴다.
- 제3자 : 이 기준 작성에 참여하지 않은 사람. 봉인본 문서만 제공하고 구두 설명은 하지 않는다. 합의 라벨을 만들지 않는다. 팀원 개인 페이지를 제3자가 읽는 것은 동의 범위 안이다 ( 사용자 확인 2026-10-03 ).
- 파일럿 프롬프트를 본 개발에 재사용하면 본실험 라벨링 자체를 제3자가 한다 ( 프로젝트 지침 4 장 ).
- 관문 미달이면 본실험 라벨 전부 폐기. 부분 재라벨은 없다.
